# Introducing Parla: i18n where the types know what loaded

Most i18n bugs aren't translation bugs: a missing key, a `{count}` nobody passed, a namespace read
before it loaded. TypeScript could catch each. Today's libraries type keys but not params, or leave
"is it loaded?" to a `ready` flag.

Parla is a type-safe i18n library for TypeScript, with React bindings. A compiler turns ICU or
MessageFormat 2 catalogs into typed functions and lazy chunks, one per locale and namespace.

```tsx
import { checkout } from './parla/namespaces/checkout.js';

const { t } = useParla([checkout]);

t.checkout.cart.items({ count: 3 }); // count: number, required
t.checkout.terms({ link: (c) => <a href="/terms">{c}</a> });
```

- **Params come from the message**: a plural's number, a select's params per branch, a renderer per
  tag.
- **`t` is proof of loading**: reading a namespace you didn't load is a type error.
- **Namespaces are imports**: the bundler ships only what you import.
- **No flash on switch**: `setLocale` loads first, then switches.
- **ICU and MF2**, per namespace.

It's 2.7 kB gzipped with the React bindings, and formats a plain message at over 35M/s, against
about 0.9M/s for i18next ([parla-benchmark](https://github.com/marcalexiei/parla-benchmark)). How it
compares with other libraries: [Why Parla](/why).

No idea here is new. Parla combines:

- namespaces and fallbacks, from [i18next](https://www.i18next.com);
- ICU messages formatted through `Intl`, from [FormatJS](https://formatjs.github.io);
- catalogs compiled ahead of time, from [Lingui](https://lingui.dev);
- messages as tree-shakable functions, from [Paraglide](https://paraglidejs.com);
- params typed from the message, from [typesafe-i18n](https://github.com/codingcommons/typesafe-i18n);
- [MessageFormat 2](https://messageformat.unicode.org), the Unicode standard for message syntax.

```sh
pnpm add @parlajs/react
pnpm add -D @parlajs/compiler
```
